# NEIRA frontend

SPA на React, Vite и TypeScript. Регистрация, вход, восстановление сессии, выбор workspace, приглашения, управление участниками, внутренние уведомления, каналы связи, контакты, обращения и просмотр диалогов подключены к backend. Прежний демонстрационный интерфейс каналов сохранён отдельно на `/preview/channels`. Старый кабинет и добавленный пример Miro в корне рабочей папки служат источниками дизайна и структуры; их старые обходные решения сюда не переносились.

## Запуск и проверки

Нужны Node.js >=22.22 и Yarn 1.22.22. Из `frontend/`:

```sh
yarn install --frozen-lockfile
yarn dev
yarn typecheck
yarn lint
yarn format:check
yarn build
```

`yarn format` форматирует проект, `yarn lint:fix` исправляет доступные ESLint-ошибки.

Vite проксирует `/api` на `http://127.0.0.1:8000`. Для локальной авторизации открывай frontend по `http://localhost:5173`: этот адрес должен совпадать с `FRONTEND_ORIGIN` backend. Для регистрации и входа нужен запущенный backend с применённой миграцией и PostgreSQL; для подтверждения почты и восстановления пароля настрой SMTP в `backend/.env`.

## Структура

Используем три слоя:

- `src/app/` — сборка приложения, маршруты, провайдеры, i18n и глобальные стили;
- `src/features/` — бизнес-модули `auth`, `settings`, `channels`, `chats`, `funnels`, `workspaces`, `members`, `invitations`, `notifications`, `dashboard-layout`, `not-found`, `error-boundary`, `change-language` и `change-theme` с их UI, состоянием, запросами и переводами; `channels-preview` содержит только старые макетные экраны;
- `src/shared/` — Axios-инстансы и интерцепторы, сгенерированные OpenAPI-типы, UI-примитивы и общие утилиты.

`app` собирает модули из `features`; модули используют `shared` и при необходимости публичный `index.ts` другого модуля без циклических импортов. Внутри модуля используются относительные импорты. `LanguageSwitcher` находится в `features/change-language`, базовые поля, кнопки, карточки и логотип — в `shared/ui`.
ESLint проверяет направление импортов между слоями и запрещает обход публичного API другого модуля.

Короткие обязательные правила размещения кода и данных записаны в [`AGENTS.md`](AGENTS.md).

Маршруты объявлены в `src/app/router.tsx` через `createBrowserRouter`, а `RouterProvider` подключён в `src/app/main.tsx`. `/` перенаправляет на `/settings` через loader. Гостевая и защищённая проверки читают одно состояние из `AuthProvider`; визуальные лаяуты не проверяют доступ. Защищённая ветка сначала проверяет вход. Для workspace-зависимых страниц требуется выбранное пространство; `/notifications` доступен авторизованному пользователю и без членства в workspace. `/auth/select-workspace` собирается в `features/workspaces` и использует общий auth-лаяут. Публичный `/invites/:token` открывает приглашение до входа и возвращает пользователя к подтверждению после авторизации; регистрация по приглашению добавляет его в указанное пространство после подтверждения email, если приглашение ещё действует. Только ветка `/preview/channels` подключает демонстрационные данные; основной `/channels` не использует моки. Экраны загружаются через `lazy`, а `*` показывает 404. Общий загрузочный экран показывается при начальной инициализации и во время навигации. Обработчики ошибок маршрутов, рендера и инициализации находятся в `features/error-boundary` и подключаются в `app`. При публикации SPA сервер должен отдавать `index.html` для frontend-маршрутов, чтобы они открывались напрямую.

Цепочка восстановления входа: `main.tsx` → `router.tsx` → `Providers` → `useQuery` в `AuthProvider` → при необходимости `/auth/refresh` → `/auth/me`. `Providers` устанавливает auth-интерцепторы до монтирования `AuthProvider`. Запрос запускается при монтировании провайдера, в том числе на странице входа; маршрутные проверки только читают его результат. HTTP 401 означает отсутствие сессии; временная ошибка сети или сервера показывает экран с повторной попыткой. После входа `AuthProvider` получает `/auth/me` и записывает пользователя в тот же кэш. Регистрация возвращает ожидающий подтверждения email без сессии. `GuestOnlyRoute` выполняет переход после входа в кабинет или к выбору workspace и сохраняет исходный защищённый адрес. Если refresh перестал работать уже после входа, клиент очищает токен и провайдер сбрасывает кэш. Данные `/auth/me` нужны для входа в кабинет и проверки членства в workspace; подписка, баланс и другие предметные данные не добавляются в auth-провайдер.

Компоненты в `shared/ui` стилизуются через Tailwind; `Button` поддерживает `asChild` через Radix Slot, `Badge` задаёт общие статусные плашки, мобильное меню и окно смены пароля используют Radix Dialog с порталом, а выбор языка и темы — Radix Select с порталом списка. Цвета компонентов берутся из семантических токенов в `src/app/index.css`. Там заданы светлая и тёмная палитры по макету; для нового элемента сначала добавляй или переиспользуй токен, а не указывай цвет в компоненте. Начальная тема выбирается по сохранённому `neira.theme` или настройке системы до первого рендера, ручной выбор сохраняется и меняется через `features/change-theme`.

Боковое меню кабинета на широком экране сворачивается до 80 px. Кнопка на его границе появляется при наведении и при фокусе с клавиатуры; выбор сохраняется в `neira.sidebar-collapsed`. Нижняя карточка аккаунта раскрывается отдельно, плавно сворачивается с учётом `prefers-reduced-motion` и сохраняет своё состояние при переключении вида меню в рамках открытого приложения. На мобильном экране меню остаётся полноразмерным в выдвижной панели.

Формы входа, регистрации, подтверждения почты и восстановления пароля используют `features/auth/api/auth-api.ts`. `shared/api/client.ts` создаёт Axios-инстансы с общим базовым URL и передачей cookie; запросы к конкретным endpoint там не размещаются. `shared/api/auth-interceptors.ts` хранит access token в памяти, добавляет его и выбранный workspace в запросы и выполняет один refresh для одновременных ответов 401. `app/providers.tsx` передаёт интерцепторам функцию refresh из `features/auth`. Регистрация проверяется Zod и содержит два обязательных согласия с офертой и обработкой персональных данных. Ссылки на оферту и политику ведут на публичный сайт NEIRA, а документ согласия раздаётся из `public/`. После регистрации `/auth/verify` проверяет шестизначный код из письма и допускает повторную отправку; только после подтверждения пользователь может войти обычным способом, включая 2FA. Для уже созданного неподтверждённого аккаунта форма входа направляет на тот же экран. Код сброса запрашивается на `/auth/forgot-password`, а новый пароль вводится на `/auth/reset-password`; ссылка в письме лишь открывает форму с подставленным email, код всё равно обязателен.

Backend возвращает короткоживущий access JWT в ответе и хранит refresh JWT в HttpOnly cookie. Access-токен остаётся только в памяти вкладки; при обновлении страницы `AuthProvider` получает новый access-токен через `/api/v1/auth/refresh` и загружает `/api/v1/auth/me` через React Query. Одновременные запросы после 401 используют один refresh и повторяются один раз. В `localStorage` хранится только идентификатор выбранного workspace. При одном membership workspace выбирается автоматически; при нескольких после входа показывается список. После обновления страницы сохранённый ID принимается только если он есть в актуальном `/auth/me`. Workspace можно сменить в настройках без повторного входа. Для tenant-scoped запросов передавай `workspace: true` в конфигурации Axios: auth-интерцептор добавит `X-Neira-Workspace-Id`, а backend проверит членство. После смены workspace сбрасывай или ключуй tenant-scoped кэш; демонстрационные каналы в preview также сбрасываются при переключении. `logout()` завершает серверный сеанс и очищает локальное состояние. Если сервер недоступен, локальное состояние очищается, но серверный отзыв cookie подтвердить нельзя: UI показывает предупреждение.

Если включена двухфакторная аутентификация, `/auth/login` возвращает временный challenge вместо JWT и cookie. Форма входа показывает отдельный шаг для кода из приложения или резервного кода и завершает вход через `/auth/login/2fa`. Challenge хранится только в состоянии формы: после перезагрузки вход начинается с пароля. Настройка 2FA в разделе «Безопасность» требует текущий пароль, локально строит QR из `otpauth_uri` и включает защиту только после проверки первого кода. Резервные коды показываются один раз после включения или обновления; при обновлении прежние коды перестают работать. Для отключения и обновления кодов требуются текущий пароль и код. Секрет и резервные коды не сохраняются в browser storage или React Query.

Администратор платформы видит в настройках вход под другим пользователем. Сначала он подтверждает свой пароль, затем ищет среди активных пользователей. Аккаунт без подтверждённой почты остаётся в списке с объяснением и недоступной кнопкой входа; сервер повторяет эту проверку при выборе. Разрешение на выбор действительно пять минут и хранится на сервере. После выбора backend выдаёт отдельный сеанс с правами выбранного пользователя. `/auth/me` возвращает данные выбранного пользователя и сведения об администраторе в `impersonation`; сверху постоянно видна плашка для возврата в собственный сеанс. При входе и выходе из режима клиент отменяет старые запросы, заменяет access-токен, очищает кэш и выбранное пространство, затем перезагружает страницу. Вкладки одного origin синхронизируют смену сеанса через storage/BroadcastChannel, а запросы, меняющие refresh cookie, сериализуются через Web Locks при поддержке браузером. Перед повтором запроса клиент сверяет `sub` и `sid` нового access-токена со старым сеансом, чтобы не отправить запрос от другой личности. После перезагрузки состояние восстанавливается через refresh cookie и `/auth/me`. Изменение пароля, 2FA и сеансы в режиме impersonation недоступны: UI скрывает настройки безопасности, а backend проверяет это сам.

`NotificationStream` в `Providers` подписывается на `/api/v1/notifications/stream` только при активном входе. SSE-запрос использует текущий Bearer access token из памяти, на 401 пробует общий refresh и повторяет подключение. После штатного закрытия соединения сервером через 60 секунд или сетевого сбоя клиент переподключается с ограниченной задержкой; при выходе подписка отменяется. События `connected` и `invalidation` запускают обновление `/auth/me` и приватных данных React Query. Redis Pub/Sub не хранит пропущенные события, поэтому каждое новое подключение сверяет состояние с PostgreSQL через обычные API-запросы.

На странице уведомлений отдельно показываются события выбранного workspace и личные приглашения. Ключи React Query включают пользователя, тип списка и workspace; счётчик в меню складывает непрочитанные события выбранного пространства и личные приглашения. Страница доступна и без выбранного workspace: в этом случае открыт список личных приглашений. Список загружается курсорными страницами по 50 записей; следующая страница запрашивается кнопкой «Показать ещё». В состоянии без пространств экран выбора даёт ссылку на уведомления, чтобы приглашение оставалось доступным.

Экран настроек показывает имя, email, Telegram, аватар и членства в workspace из `/api/v1/auth/me`. Если `avatar_url` пустой, вместо фото показывается инициал; если Telegram не указан, показывается «—». Имя и Telegram сохраняются через `PATCH /api/v1/auth/me`, а выбор или удаление аватара сразу выполняет отдельный запрос к `/api/v1/auth/me/avatar`. После успешного ответа данные `/auth/me` обновляются в общем кэше. Фото загружается как PNG, JPEG или WebP размером до 5 МБ. Раздел пространств содержит текущее пространство, участников со счётчиком и список пространств. Диалоги позволяют переименовать пространство, управлять участниками и приглашениями, переключить пространство без повторного входа. Диалог «Активные сеансы» загружает реальные устройства и позволяет завершить отдельный другой сеанс или все остальные сразу; его endpoint-функции и React Query-логика находятся в `features/settings`. В кабинете можно изменить пароль, введя текущий и новый; неверный текущий пароль показывается у поля, а после успешной смены другие сеансы завершаются. Для забытого пароля доступен отдельный гостевой сценарий через код из письма.

Основной маршрут `/channels` показывает каналы выбранного workspace. На `/channels/connect` владелец или администратор выбирает Telegram Bot либо сообщество VK, проверяет токен и при желании связывает канал с воронкой. Для VK нужен также числовой ID сообщества. Страница `/channels/:channelId` показывает сведения о канале, его состояние, название и выбранную воронку. Здесь можно проверить доступ и webhook, обновить данные провайдера, отключить, переподключить с новым токеном либо удалить канал. Отключение удаляет доступ, а повторное подключение сохраняет ID канала. Для токена и недостаточных разрешений показываются отдельные ошибки; инструкции доступны при подключении и переподключении. Менеджер и роль просмотра видят каналы без действий управления. В нижней карточке первая вкладка содержит настройки; вторую, «Трейс событий», видит администратор платформы как в собственном сеансе, так и при входе под пользователем. Список сохранённых webhook-событий загружается постранично, а исходное тело — только при раскрытии записи. Ручное обновление сбрасывает список к первой странице и запрашивает актуальные статусы; отклонённые запросы и повторные доставки в списке не отображаются. Запросы находятся в `features/channels/api`, операции и кэш — в `model`, ключи кэша включают workspace. В модуле нет моковых каналов и зависимостей от старого предпросмотра.

Старые макетные экраны изолированы в `features/channels-preview` и доступны по прямым адресам `/preview/channels`, `/preview/channels/connect` и `/preview/channels/:channelId`; в боковом меню на них ссылки нет. Их данные и изменения живут только в памяти ветки preview и не относятся к workspace. Динамические адреса строятся через `generatePath`; параметры и наличие записи проверяются при чтении.

## Управление workspaces

При обычной регистрации создаётся `My Workspace`; регистрация по приглашению добавляет пользователя только в приглашённое пространство. В настройках показываются текущее пространство и число доступных пространств. Кнопка «Управлять» открывает модальное окно с текущим и остальными пространствами: можно переключаться, создавать новые, переименовывать пространства с ролью владельца или администратора и удалять другие собственные пространства. Удаление текущего пространства через интерфейс недоступно. Если пользователь потерял последнее членство из-за удаления пространства другим владельцем, экран выбора показывает название удалённого пространства из `/auth/me` и предлагает создать своё. Профиль и сеансы при удалении пространства сохраняются.

Операции workspace принадлежат `features/workspaces`, а управление участниками и приглашениями — `features/members`. Список доступных пространств для выбора берётся из `/auth/me`; после успешной операции этот кэш обновляется из ответа API. При смене текущего workspace приватные данные прежнего контекста сбрасываются. Создание, переименование и удаление выполняются через `/api/v1/workspaces`; backend также предоставляет отдельный `GET /api/v1/workspaces`. Роли членства — `owner`, `admin`, `manager` и `reader`; права проверяет backend.

## Воронки

Страница `/funnels` находится в основном разделе меню и показывает воронки выбранного workspace. Данные загружаются с backend через `features/funnels/api` и React Query; ключ кэша начинается с `private` и включает `workspaceId`. Текущие роли позволяют изменять воронки только владельцу пространства. Переключение workspace меняет выбор и данные доски.

Каждая воронка показывает статусы колонками в порядке сервера; входящий статус всегда первый. Доска занимает доступную высоту и с пустыми колонками, а горизонтальная прокрутка дополнена полупрозрачными кнопками у краёв. Выбор воронки, режимы просмотра, поиск и меню настроек находятся в контенте страницы; кнопка создания обращения — в верхнем заголовке. Колонки отделены от панели управления линией с отступами и друг от друга мягким пунктиром; их заголовки окрашены по сохранённому цвету статуса, а описание доступно через значок вопроса. Доска получает открытые обращения и точные счётчики статусов из backend. Режим таблицы, поиск и кнопки ручного создания обращения видны, но пока не выполняют эти действия.

Страница `/contacts` показывает таблицу контактов выбранного workspace с email, телефоном, иконками каналов, датой создания и временем последней активности. Иконка канала открывает диалог в NEIRA; владелец и администратор могут изменить имя и контактные данные или удалить контакт с сохранением истории. Поиск работает по имени, внешней идентичности, email и телефону. `/contacts/:contactId` показывает аватары и сведения внешних идентичностей, ссылки на профиль и диалог у провайдера, внутренние диалоги и историю обращений. Из панели контакта в чате видны пять последних обращений с воронкой и этапом; ссылка на обращение открывает его карточку в этом разделе страницы контакта после загрузки данных. Списки загружаются страницами, а ключи React Query включают workspace, строку поиска и лимит списка обращений; открытые список и карточка обновляются раз в минуту после фонового обновления профилей провайдера. Ручное объединение контактов появится отдельным сценарием.

Страницы `/messages` и `/messages/:conversationId` показывают список диалогов и историю сообщений выбранного workspace. Оба списка загружаются страницами по 50 записей; следующая страница диалогов и более старые сообщения подгружаются при прокрутке. Входящие сообщения отмечаются прочитанными только после появления в видимой части истории активной вкладки через `IntersectionObserver`; API принимает список конкретных ID, поэтому невидимые сообщения остаются непрочитанными. Сайдбар получает отдельный точный счётчик непрочитанных сообщений всего workspace, независимо от того, сколько страниц списка загружено.

Входящие фото, файлы и голосовые сообщения Telegram Bot и VK Community показываются в истории вместе с подписью, если она есть. Несколько частей одного сообщения идут в порядке сервера. Для файла показываются имя, размер и действие скачивания; голосовое воспроизводится в плеере. В списке диалогов и тосте сообщение без подписи обозначается «Фото», «Файл» или «Голосовое сообщение». Медиа читаются из приватного S3 по временным ссылкам API. Для фото клиент проверяет срок ссылки и при необходимости обновляет её через `GET /conversations/{conversationId}/messages/{messageId}`; перед скачиванием файла и воспроизведением голосового этот запрос выполняется заново, чтобы использовать действующую ссылку. Ключ объекта и S3-секреты frontend не получает.

Аватар в списке и заголовке внешнего диалога берётся из его основного участника, а рядом с сообщением — из автора конкретного сообщения. У входящего сообщения он стоит слева, у исходящего — справа; исходящее из кабинета показывает пользователя NEIRA, а ответ, отправленный непосредственно в канале, — сообщество. На аватар в списке наложена иконка канала. В заголовке внешнего диалога есть прямая ссылка на профиль у провайдера, когда она доступна. Нажатие на имя или аватар в заголовке либо входящего сообщения открывает панель контакта: данные выбранной идентичности, доступные ссылки провайдера и переход в полную карточку. Нажатие на имя или аватар исходящего сообщения открывает панель его фактического автора: профиль пользователя NEIRA или сведения канала. Контакт загружается через `GET /contacts/{contactId}`, а автор исходящего — через `GET /conversations/{conversationId}/messages/{messageId}/author` только при открытии панели, отдельно для выбранного workspace. Если запись недоступна, чат остаётся открытым и показывает объяснение вместо данных. На широком экране панель занимает третью колонку, на узком перекрывает чат и закрывается кнопкой или Escape. Событие `profile` в SSE обновляет данные диалога, его сообщений и открытой панели без изменения счётчика непрочитанных, тоста и звука.

Глобальная workspace-подписка SSE обновляет данные по сигналам сервера и показывает тост только при новом входящем сообщении; тост и звук не создают запись во внутренних уведомлениях. Сигнал `history` для добавленной задним числом истории обновляет списки без тоста и звука. После восстановления SSE список сверяется с сервером, но тост и звук для событий, пришедших во время разрыва соединения, не гарантируются: Redis Pub/Sub не хранит историю сигналов. Звук можно отключить в заголовке диалога, настройка сохраняется в браузере. Браузер разрешает звук после первого действия пользователя. Файлы `public/sounds/message-notification.mp3` и `.ogg` получены из [Simple Happy Beep](https://commons.wikimedia.org/wiki/File:Simple_Happy_Beep.ogg) автора waveplaySFX; лицензия [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/) допускает коммерческое использование без указания авторства. Компактное поле ввода отправляет текст во внешние диалоги Telegram Bot и VK Community через `POST /conversations/{conversationId}/messages`, а несколько фото JPEG/PNG/WebP до 10 МБ каждое и файлов до 20 МБ каждый — через `POST /conversations/{conversationId}/messages/media`. Можно добавлять вложения повторным выбором, удалять их по одному и вставлять несколько фото из буфера. Перед отправкой показываются все выбранные вложения и число сообщений: каждые 10 образуют отдельное сообщение, а Telegram дополнительно разделяет фото и файлы по типу. Пачки отправляются по порядку с отдельным UUID; необязательная подпись до 1024 символов относится только к первой. Если отправка остановилась после сохранения части пачек, сохранённые удаляются из черновика, а остальные остаются для следующей попытки. Панель эмодзи рядом с меню вложений открывается при наведении мышью или нажатии, вставляет символ в позицию курсора в сообщении или подписи и закрывается после ухода курсора, по Escape либо клику вне панели. После сохранения сообщения на сервере форма очищается даже при ошибке доставки: неотправленное сообщение находится в нижнем блоке, а красный статус показывает причину по наведению или фокусу. Меню статуса позволяет повторить или отменить своё неотправленное сообщение; меню раздела повторяет или отменяет все свои неотправленные сообщения в диалоге, включая не загруженные в текущую страницу истории. Групповой повтор идёт последовательно по снимку ID и обновляет кэш после завершения; при неопределённой доставке он останавливается. Если ошибка произошла до сохранения, черновик и его UUID остаются для повтора; неопределённая доставка без подтверждения сохранения блокирует повтор до проверки истории. Поиск и индикатор набора текста пока не подключены.

Меню с шестерёнкой открывает создание, настройку и удаление воронки. При создании новая воронка получает редактируемый набор из пяти статусов. В том же диалоге настройки можно изменить имя, описания, цвета и порядок статусов, добавить или удалить этапы; весь набор сохраняется одним запросом. CSS-токены задают цвета в светлой и тёмной темах. На доске вторичные статусы переставляются через dnd-kit за любую свободную область заголовка мышью, касанием или клавиатурой; входящий этап меняется отдельным действием. Подсказки описания и входящего индикатора выводятся через Radix Tooltip рядом с соответствующими иконками поверх прокручиваемой доски. Запросы выполняются через tenant API с `X-Neira-Workspace-Id`.

Перед удалением воронки диалог запрашивает список активных привязанных каналов и предупреждает, что они остановятся. Пока результат проверки не получен, удаление недоступно. После удаления список каналов обновляется; в карточке остановленного канала показана причина и действие переподключения.

## Типы API

При запущенном backend команда ниже получает `/openapi.json` и обновляет `src/shared/api/generated/schema.ts`:

```sh
yarn api:generate
```

Можно указать другой URL или путь к локальному JSON/YAML-файлу: `yarn api:generate ./schema.json`. Генератор использует `openapi-typescript`; текущая схема содержит health, auth, sessions, workspaces, участников, приглашения, уведомления, воронки, каналы, контакты, обращения и диалоги. Сгенерированный файл не редактируется вручную. Для проверки ввода регистрации и ответа `/me` используется Zod; OpenAPI-типы сами по себе runtime-валидацию не выполняют.

## Переводы

Приложение использует `i18next` и `react-i18next` с локальными словарями. Поддерживаемые языки, русский fallback и ключ хранения выбора находятся в `src/shared/i18n/languages.ts`. При запуске язык берётся из сохранённого ручного выбора, затем из настроек браузера; если подходящего перевода нет, используется русский. Автоматически определённый язык не сохраняется. Переключатель сохраняет ручной выбор и обновляет `html lang` и `dir`.

Строки интерфейса размещай рядом с их владельцем: например, переводы 404 лежат в `src/features/not-found/i18n/translations.ts`. Для нового модуля добавь словари `ru` и `en`, экспортируй их через `index.ts`, зарегистрируй namespace в `src/app/i18n/resources.ts` и используй `useTranslation('namespace')` в компонентах. Русский словарь задаёт ключи; TypeScript проверяет их наличие в английском. Общие строки приложения хранятся в `src/app/i18n/translations.ts`. Название продукта и технические идентификаторы не переводятся.

Сейчас словари включены в сборку. Сетевой загрузчик переводов не нужен, пока объём словарей или способ управления ими не потребует отдельного решения.
