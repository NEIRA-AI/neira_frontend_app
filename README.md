# NEIRA frontend

SPA на React, Vite и TypeScript. Экраны авторизации, настройки кабинета и состояния приложения сейчас представляют собой UI-каркас: формы не отправляют запросы, настройки не сохраняются, а доступ к кабинету ещё не проверяется. Старый кабинет и добавленный пример Miro в корне рабочей папки служат источниками дизайна и структуры; их API, сессии и старые обходные решения сюда не переносились.

## Запуск и проверки

Нужны Node.js >=22.22 и Yarn 1.22.22. Из `frontend/`:

```sh
yarn install --frozen-lockfile
yarn dev
yarn typecheck
yarn lint
yarn format:check
yarn build
```

`yarn format` форматирует проект, `yarn lint:fix` исправляет доступные ESLint-ошибки.

## Структура

Используем Feature-Sliced Design небольшими шагами:

- `src/app/` — точка сборки приложения, маршруты, провайдеры, обработка ошибок и глобальные стили;
- `src/pages/` — страницы входа, регистрации, проверки кода, настроек, технической главной и 404;
- `src/widgets/` — композиция экранов авторизации и кабинета;
- `src/features/` — пользовательские действия смены языка и темы;
- `src/shared/` — переиспользуемые UI-примитивы, настройка языков, маршруты и сгенерированные типы API.

Слой `entities` появится вместе с предметными данными. Импорты идут от верхнего слоя к нижнему. Другой срез подключается через его публичный `index.ts`; внутри среза используются прямые относительные импорты. `LanguageSwitcher` находится в `features/change-language`, поскольку меняет и сохраняет пользовательский выбор; базовые поля, кнопки, карточки и логотип находятся в `shared/ui`.

Маршруты объявлены в `src/app/router.tsx` через `createBrowserRouter`, а `RouterProvider` подключён в `src/app/main.tsx`. Корневой `App` содержит `<Outlet />`. Дочерние ветки собирают `AuthLayout` для `/auth/sign-in`, `/auth/sign-up`, `/auth/verify` и `CabinetLayout` для `/` и `/settings`. Лояуты и страницы загружаются через `lazy`, поэтому код мобильного меню не входит в начальную загрузку страниц входа; `*` показывает общую страницу 404. `ProtectedLayout` уже стоит перед кабинетной веткой, но сейчас только возвращает `<Outlet />`: проверка сессии и перенаправления появятся вместе с авторизацией. Общий загрузочный экран показывается при начальной инициализации и после короткой задержки во время навигации. Для ошибок маршрутов и рендера указан `RouteErrorBoundary`, а снаружи роутера есть `RootErrorBoundary`; сбой инициализации переводов показывает статический экран ошибки. Ошибки обработчиков событий и будущих запросов обрабатываются в их собственных сценариях. При публикации SPA сервер должен отдавать `index.html` для frontend-маршрутов, чтобы они открывались напрямую.

Компоненты в `shared/ui` стилизуются через Tailwind; `Button` поддерживает `asChild` через Radix Slot, `Badge` задаёт общие статусные плашки, мобильное меню и окно смены пароля используют Radix Dialog с порталом, а выбор языка и темы — Radix Select с порталом списка. Цвета компонентов берутся из семантических токенов в `src/app/index.css`. Там заданы светлая и тёмная палитры по макету; для нового элемента сначала добавляй или переиспользуй токен, а не указывай цвет в компоненте. Начальная тема выбирается по сохранённому `neira.theme` или настройке системы до первого рендера, ручной выбор сохраняется и меняется через `features/change-theme`.

Боковое меню кабинета на широком экране сворачивается до 80 px. Кнопка на его границе появляется при наведении и при фокусе с клавиатуры; выбор сохраняется в `neira.sidebar-collapsed`. Нижняя карточка аккаунта раскрывается отдельно, плавно сворачивается с учётом `prefers-reduced-motion` и сохраняет своё состояние при переключении вида меню в рамках открытого приложения. На мобильном экране меню остаётся полноразмерным в выдвижной панели.

В слоях страниц находятся разметка и небольшое локальное UI-состояние (например, видимость пароля и предпросмотр полей). Формы авторизации после отправки явно сообщают, что это предварительный просмотр; регистрация содержит два обязательных согласия с офертой и обработкой персональных данных. Ссылки на оферту и политику ведут на публичный сайт NEIRA, а документ согласия раздаётся из `public/`. Запросы, авторизация и сохранение данных пока отсутствуют.

Страница настроек показывает образец профиля из основного экрана Figma. В режиме редактирования можно изменить имя и просмотреть загрузку или удаление аватара; изменения живут только в состоянии открытой страницы. Контактный селект готов принимать список связанных контактов, но в каркасе показывает только текущий `@username`: значения из других кадров макета не объединяются в выдуманный аккаунт. Диалог пароля воспроизводит ввод, ошибку несовпадения и экран шестизначного кода, но не меняет пароль и не отправляет письмо. Подтверждение кода явно сообщает об этом. При подключении API локальное состояние нужно заменить данными аккаунта и настоящими запросами, а образцы удалить.

Адреса существующих страниц хранятся в `src/shared/routes.ts`. Динамических маршрутов пока нет, поэтому нет и фиктивных типов параметров. В режиме Data Router React Router не генерирует типы маршрутов автоматически, а объявление `Register.params` не используется библиотекой. Вместе с первым динамическим маршрутом добавьте типизированную функцию построения URL на основе `generatePath` либо явную регистрацию `Register.pages` для `href`; параметры из `useParams` проверяйте во время выполнения перед использованием.

## Типы API

При запущенном backend команда ниже получает `/openapi.json` и обновляет `src/shared/api/generated/schema.ts`:

```sh
yarn api:generate
```

Можно указать другой URL или путь к локальному JSON/YAML-файлу: `yarn api:generate ./schema.json`. Генератор использует `openapi-typescript`; в текущем backend схема содержит только health endpoints. Сгенерированный файл не редактируется вручную. Zod предназначен для runtime-валидации там, где она потребуется; OpenAPI-типы сами по себе runtime-валидацию не выполняют.

## Переводы

Приложение использует `i18next` и `react-i18next` с локальными словарями. Поддерживаемые языки, русский fallback и ключ хранения выбора находятся в `src/shared/i18n/languages.ts`. При запуске язык берётся из сохранённого ручного выбора, затем из настроек браузера; если подходящего перевода нет, используется русский. Автоматически определённый язык не сохраняется. Переключатель сохраняет ручной выбор и обновляет `html lang` и `dir`.

Строки интерфейса размещай рядом с их владельцем: например, переводы страницы 404 лежат в `src/pages/not-found/i18n/translations.ts`. Для нового среза добавь словари `ru` и `en`, экспортируй их через `index.ts`, зарегистрируй namespace в `src/app/i18n/resources.ts` и используй `useTranslation('namespace')` в компонентах. Русский словарь задаёт ключи; TypeScript проверяет их наличие в английском. Общие строки приложения хранятся в `src/app/i18n/translations.ts`. Название продукта и технические идентификаторы не переводятся.

Сейчас словари включены в сборку. Сетевой загрузчик переводов не нужен, пока объём словарей или способ управления ими не потребует отдельного решения.
