# Правила frontend NEIRA

Перед изменениями прочитай `README.md`, а для бизнес-логики — также `../docs/PRODUCT.md` и `../docs/ARCHITECTURE.md`.

## Слои и зависимости

- `app` собирает маршруты, провайдеры, i18n и глобальные стили. Предметные экраны, запросы и формы принадлежат `features`.
- `features/<модуль>` владеет своим UI, состоянием, API и переводами. Создавай модуль для самостоятельной области или сценария, а не для отдельного обработчика; добавляй `ui`, `model` и `api` по мере необходимости.
- `shared` содержит транспорт запросов, сгенерированные типы OpenAPI, UI-примитивы и общие утилиты. Предметные endpoint размещай в `api` модуля-владельца, а не в `shared`.
- Соблюдай направление зависимостей `app → features → shared`. Между модулями обращайся через публичный `index.ts`, внутри модуля — через относительные импорты; избегай циклов. Маршрутный `lazy()` может напрямую импортировать `*.page.tsx`.

## Композиция и хуки

- `*.page.tsx` собирает экран, вызывает нужные хуки и передаёт их результаты UI. Отдельный композиционный компонент связывает несколько самостоятельных операций с одним блоком UI, когда это упрощает страницу; каталог `compose/` не обязателен. Простая форма может вызывать свой хук напрямую.
- `ui/` владеет разметкой, состоянием полей, запуском валидации и простым поведением вроде открытия и фокуса. Связанный черновик формы можно вынести в узкий хук рядом с UI, если обработчики мешают читать компонент. Технические браузерные процессы со своим жизненным циклом (например, превью файла с очисткой) размещай в `features/<модуль>/hooks/use-<задача>.ts`; чистые расчёты — в обычных функциях рядом с владельцем. Не создавай хук для одного переключателя.
- `model/use-<операция>.ts` отвечает за одну предметную операцию: запрос или мутацию, состояние процесса, кэш и связанные переходы; HTTP-функции принадлежат `api/`. Координирующий хук допустим для одного тесно связанного многошагового процесса. Не объединяй независимые операции в `useXPage` или хук, названный по UI-компоненту, и не добавляй прослойку ради формально пустого файла.

## Маршруты и данные

- Дерево маршрутов находится в `app`; проверки доступа отделены от визуальных лаяутов. Динамические адреса строй через `generatePath`, а параметры и наличие данных проверяй при чтении.
- Серверные данные и их кэш веди через React Query; локальное состояние держи у ближайшего владельца. При смене пользователя или workspace разделяй кэш ключами или очищай его, чтобы не показывать данные другого контекста.
- Типы API бери из сгенерированной OpenAPI-схемы; Zod применяй там, где нужна проверка данных во время выполнения.

Перед завершением изменений выполняй подходящие `yarn typecheck`, `yarn lint`, `yarn format:check` и `yarn build`. Обновляй README и корневой архитектурный документ, если меняется схема работы приложения.
